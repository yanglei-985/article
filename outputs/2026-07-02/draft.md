今天这条 GitHub Trending 很适合「AI习语」读者：它表面上是一个 Agent 仓库，实际上提醒我们一件事——提示词正在从“写一句话”升级为“设计一个可复用的专家岗位”。

项目叫 `agency-agents`，作者把它描述为“放在你手边的一整套 AI agency”。里面不是零散 prompt，而是一组带有专业分工、性格、工作流程和交付标准的 AI 专家：从前端开发、UI 设计，到 Reddit 社区运营、创意润色、现实校验等。

它的核心价值不在于“又多了很多提示词”，而在于把 AI 使用方式产品化：每个 agent 都有身份设定、核心任务、沟通风格、可交付成果、成功指标。换句话说，它不是让 AI 临时扮演一个角色，而是让 AI 像一个稳定岗位一样工作。

项目现在还提供了桌面应用 `Agency Agents`，支持 macOS、Linux 和 Windows。你可以在应用里浏览完整 agent 名单，并一键安装到 `Claude Code`、`Cursor`、`Codex`、`Gemini CLI`、`OpenCode`、`Qwen`、`Osaurus` 等工具中。官方强调：不需要 clone 仓库，不需要跑脚本，并且可以自动更新。

如果你更习惯命令行，也可以用脚本安装。比如把全部 agents 安装到 `Claude Code`，或者只选择 `engineering`、`security` 这样的 division；也可以只安装 `frontend-developer`、`ui-designer` 这类单个 agent。项目还支持把 agents 转换成多种工具可用的集成文件。

为什么这件事值得关注？因为很多人使用 AI 的瓶颈，不是模型不够强，而是每次都从零开始解释背景、角色、标准和输出格式。`agency-agents` 的思路是：把高频任务沉淀为“岗位说明书”。你不是每次都说“帮我写个页面”，而是直接调用一个熟悉交付标准的前端开发 agent。

给你一个可直接复用的方法：为自己的高频任务写一张 `Agent Card`。它不需要很长，但要包含五层信息。

第一层是身份：这个 agent 是谁，擅长什么，不做什么。第二层是任务：它要解决哪类问题，默认目标是什么。第三层是流程：它先问什么、再判断什么、最后交付什么。第四层是交付物：输出代码、方案、清单、改写稿，还是对比表。第五层是成功标准：怎样算完成，怎样算质量好。

你可以直接复制这个提示词模式：

`你是一个[岗位/专家类型]。你的任务是帮助我完成[具体任务类型]。你需要先确认[关键信息]，再按照[工作流程]处理。输出必须包含[交付物清单]。请用[语气/风格]表达，并用[成功标准]自检。如果信息不足，先问不超过3个澄清问题。`

举个例子，如果你经常用 AI 学英文，可以写一个 `English Expression Coach`：它的任务不是泛泛“帮我学英语”，而是把中文想法改写成自然英文，解释关键表达，指出中式英语风险，并给出 3 个可替代表达。成功标准是：自然、准确、可复用，且保留你的原意。

这也是语言学习者特别应该注意的一点：保留英文术语。比如 `agent`、`workflow`、`deliverable`、`success metrics` 这些词，不要急着全部翻译掉。它们是 AI 工具世界的基本词汇。你每次设计 agent，其实也在训练自己用英文抽象任务、定义流程和描述标准。

我建议你今天做一个小练习：选一个你每周至少做三次的任务，例如写公众号标题、润色英文邮件、拆解论文、生成短视频脚本、检查代码。然后不要直接写 prompt，而是先写一张 `Agent Card`。写完后，把它固定到你常用的 AI 工具里，连续使用一周，再根据输出质量修改它。

从提示词到 agent，本质上是从“临场表达”走向“系统设计”。会写 prompt 的人能让 AI 完成一次任务；会设计 agent 的人，能让 AI 持续稳定地承担一类工作。
