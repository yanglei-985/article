## Claude Code 团队的一个重要信号：提示词正在变短，工作正在变大

如果你还在把 AI 当成一个需要逐步盯着的实习生，Anthropic 的 Claude Code 团队已经在换一种工作方式：少写提示词，更多授权；少问“它会不会出错”，更多问“我能不能把任务设计得更大”。

这篇内容来自 Simon Willison 对 Anthropic Claude Code 团队成员 Cat Wu 和 Thariq Shihipar 的炉边访谈。访谈谈到 Claude Code、Claude Tag、Fable、编码代理安全、评估、工具设计，以及 Anthropic 内部如何使用这些工具。

最值得注意的数字是：Claude Tag，也就是 Claude 面向 Slack 的协作集成，已经为 Claude Code 团队贡献了 65% 的产品工程 PR。Claude Code 的新功能会先发给 Anthropic 内部员工使用，只有能证明内部用户留存的功能，才会继续推向外部用户。

这不是一个普通的“公司工具更新”。它更像是一个信号：AI 编码代理正在从“帮你写代码”变成“嵌入团队协作流程”。

---

## 1. 从“盯着每一步”到“把实现交出去”

Cat Wu 回忆，Claude Code 刚随 Claude Sonnet 3.7 推出时，使用方式非常谨慎。你给它一个任务，必须仔细盯着它的每一个动作，认真阅读每一次权限确认，经常要说“不”，还要追问它有没有检查这个文件、那个文件。

但随着模型能力迭代，团队逐渐可以后退一步，把更多琐碎实现交给 Claude。人的时间被释放出来，用来思考更高层的问题：既然 Claude Code 已经能实现很多东西，我们到底应该为用户设计什么样的体验？

Thariq 的说法更直接。他说自己几乎已经忘了过去还要不断点击 yes 和 allow。Auto mode 像是突然变成了默认现实。而 Fable 又带来一个新变化：很多功能现在可以 one-shot，一次性生成可用版本。

对普通读者来说，这里的重点不是“某个模型更强了”，而是角色分工变了：AI 不再只是执行你拆好的小步骤，而是开始承接完整的实现闭环。

---

## 2. 更强的 AI，不是让你做更少的事，而是让你做更大的事

访谈里有一个很有意思的表达：Thariq 建议用“更有野心”来抵消 coding agent 带来的 Deep Blue 式冲击。这里的 Deep Blue 指的是国际象棋被机器击败后，人类能力感受到的心理落差。

他的意思是：当代理能把很多实现细节吃掉时，人不应该退回去做更小的任务，而应该提高任务上限。以前你可能一天只敢改一个小功能；现在你应该问：我能不能设计一个完整体验、一次重构一条流程、做一个以前嫌麻烦的内部工具？

这也是 AI习语最想提醒的一点：AI 提效的真正收益，不是“同样的活更快完成”，而是“以前不值得做、不敢做、做不起的事，现在可以开始做”。

---

## 3. 提示词也在变化：少给例子，少列禁令

访谈中另一个非常反直觉的点是：对 Fable 5，甚至 Opus 4.8 这类新模型来说，在 system prompt 里添加大量示例，已经不再是最佳实践。Claude Code 的 system prompt 最近缩小了 80%。

同样，那种长长的“不要做 X、不要做 Y”的禁令清单，也可能降低最新模型的输出质量。

这和很多人过去学到的提示词方法不同。早期模型需要更多示例、更多边界、更多禁止项，才能稳定输出。但模型能力提升后，过度提示反而可能像噪音，让模型在执行时被不必要的规则牵制。

更好的方向是：把提示词从“控制每一步”改成“定义目标、约束和验收标准”。也就是少写过程，多写结果；少写恐惧，多写判断标准。

---

## 4. 可直接使用：代理型任务委派卡

下次你让 AI 做一个复杂任务，不妨别急着写一长串步骤，而是用下面这个结构：

**任务：**你要完成什么，不要只描述动作，要描述业务结果。

**背景：**当前项目、读者、用户、限制条件是什么。

**边界：**哪些文件、数据、风格、风险点需要注意。

**完成标准：**怎样才算做好，最好给出可检查的验收标准。

**复盘方式：**完成后请它解释改了什么、为什么这样改、还有哪些不确定。

可以直接复制这个提示词：

> 你是我的 AI 执行代理。请先理解任务目标，再自主规划实现步骤。\n\n任务目标：{写清楚最终结果}\n背景信息：{项目、用户、上下文}\n边界条件：{不能改什么、必须遵守什么、风险点}\n完成标准：{可检查的验收条件}\n输出要求：先给出简短计划；执行后总结改动、关键判断和仍需人工确认的地方。不要用过长的禁令清单，优先围绕目标和验收标准工作。

这个模式适合写代码、改文章、做调研、整理资料，也适合英文学习。比如你可以把“修改一篇英文邮件”改成“让收件人更快理解请求并愿意回复”，AI 的工作质量通常会明显不同。

---

## 5. 给英文学习者的一个小动作

这篇访谈本身也很适合做英文输入训练。建议你从原文里抓 5 个工作流相关表达，而不是背技术名词：delegate、one-shot、auto mode、dogfooding、retention。

学习方式很简单：每个词不只查中文意思，而是写一句“我如何在自己的工作里使用它”。例如：I can delegate repetitive formatting tasks to AI, but I should still review the final structure.

这样学英文，会更接近真实工作语言。你学到的不是单词，而是 AI 时代描述工作的方式。

---

## 6. 结论

Claude Code 团队的经验给我们三个提醒：第一，AI 工具会先改变内部工作流，再改变产品形态；第二，提示词正在从“详细遥控器”变成“任务委派书”；第三，真正的提效不是省时间，而是把目标设得更高。

如果你今天只带走一个动作：下次用 AI，不要先问“我该让它做哪一步”，先问“我想交付的完整结果是什么”。
