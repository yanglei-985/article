过去两年，我们和编程智能体协作的默认方式，是写一个好提示词，补足上下文，等待回复，再继续追问。但 Addy Osmani 在 Loop Engineering 里提出了一个更值得关注的变化：真正重要的能力，正在从“会提示智能体”转向“会设计提示智能体的循环”。

所谓 Loop Engineering，不是让 AI 反复跑同一个命令，而是设计一个能持续发现任务、分发任务、检查结果、记录状态、决定下一步的小系统。你不再是每一步都亲自输入 prompt 的人，而是设计一个循环，让它替你驱动 agent 工作。

这对「AI习语」的读者很重要。因为它不仅是写代码的工作流变化，也是一种新的提示效率思维：从单次提问，升级到可复用、可检查、可积累的系统。



先看核心变化：提示词没有消失，但位置变了。原文引用了 Peter Steinberger 的说法：你不应该再提示编程智能体，而应该设计会提示智能体的循环。Claude Code 负责人 Boris Cherny 也说，他现在的工作不是提示 Claude，而是写 loops。

这句话容易被误解。它不是说 prompt 没用了，而是说 prompt 不再只是一次性的输入。更高级的做法，是把提示词放进一个流程：什么时候运行、读取什么信息、交给哪个 agent、如何验证、结果写到哪里、下一轮如何继续。

单次 prompt 像一次对话；loop 像一个工作制度。前者依赖你随时盯着，后者依赖系统自己推进。



一个可运行的 loop，需要五个能力，再加一个记忆层。第一是 Automations，也就是按计划自动运行的任务。它负责定期发现问题，比如每天检查 CI 失败、issue、最近提交，或者做 bug triage。

第二是 Worktrees，用来隔离并行工作。多个 agent 同时改代码时，如果都在同一个目录里工作，很容易互相覆盖。git worktree 相当于给每个 agent 一个独立工作区。

第三是 Skills，把项目知识写下来。比如构建步骤、代码风格、禁用做法、历史坑位。它减少每次重新解释项目背景的成本。

第四是 Plugins 和 Connectors，让 loop 能连接真实工具，比如 Linear、GitHub、Slack、数据库、staging API。一个只能看文件系统的 agent，很难变成真正的工作流。

第五是 Sub-agents，也就是把“执行者”和“检查者”分开。写代码的 agent 不应该自己给自己判卷，另一个 agent 应该负责审查、验证、找漏洞。

第六是 State，也就是外部记忆。可以是 Markdown 文件，也可以是 Linear 看板。关键是它必须存在于单次对话之外，因为模型会忘，仓库和文件不会忘。



最关键的认知是：记忆不该只放在上下文里。很多人用 AI 工具效率不稳定，问题不在模型，而在记忆位置放错了。

如果你每次都把背景重新塞进上下文，agent 每次都像新员工入职。它会猜测你的意图，也会自信地补全你没有说清的地方。Skills 和 State 的价值，是把长期意图写在外部，让每一次运行都能继承前一次的结果。

这也是语言学习可以借鉴的地方。不要每次都对 AI 说：请帮我提升英语。你应该有一个长期文件，记录你的常犯错误、目标表达、输出主题、复习计划。AI 每次读取它，再生成下一轮练习。



给你一个今天就能用的“英文输入到输出”每日循环。第一步，Discovery：每天让 AI 从一篇英文文章中提取 5 个高价值表达、3 个观点和 1 个可迁移方法。

第二步，Skill：维护一个固定说明文件，写清你的英语水平、行业方向、表达偏好和禁用翻译腔。第三步，Practice：让 AI 基于当天内容生成 3 个中译英句子、1 段英文复述、1 个口语回答。

第四步，Checker：让另一个 AI 角色只负责挑错，检查语法、搭配、语气和逻辑。第五步，State：把今天的错误、好表达、待复习项写入 Markdown 学习日志。第六步，Next：第二天先读取日志，再决定复习什么、增加什么新练习。

你会发现，真正提升效率的不是某一个神奇 prompt，而是这个循环每天都能接着昨天往前走。



可直接复制的提示词模式：

你是我的 AI 学习与写作 loop 管理器。请读取我提供的学习日志和今天的英文材料，完成以下任务：1）提取今天最值得学习的英文表达；2）基于我的水平生成输出练习；3）用另一个审稿人视角检查我的答案；4）把错误、改写建议和明天要复习的内容整理成 Markdown 状态记录。请不要只给一次性建议，要让结果能被明天继续使用。

这个模板的重点不是内容多，而是有三个动作：读取状态、生成任务、更新状态。只要这三个动作稳定存在，你就在做最小版本的 Loop Engineering。



AI习语视角看，未来的高手，不只是会问问题。AI 使用能力正在从“表达需求”升级为“设计系统”。

提示词仍然重要，但它会越来越像系统里的一个零件。更稀缺的能力，是把任务拆成可循环的流程，把经验写成 skills，把结果沉淀成 state，把检查交给独立角色。

对写作者、学习者、产品经理和程序员来说，这都是同一个方向：不要只追求一次回答更漂亮，而要让 AI 每天更懂你的目标、更少重复、更能自我推进。
